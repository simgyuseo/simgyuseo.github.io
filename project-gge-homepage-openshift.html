[경기도교육청][홈페이지재구축프로젝트] OpenShift Cluster 기술지원

2025.05.09 ~ 2025.07.22

OpenShift
역할OpenShift Cluster 기술지원 · 리소스 제한 설정 · Jenkins 설치 · 이슈 트러블슈팅
핵심 성과istio-cni Unauthorized 및 Client IP/Pod CIDR 중복 무한루프 이슈 해결, Private OpenShift 운영 경험 축적
① 문제 발견
  • 상황: 경기도교육청 홈페이지 재구축 사업에서 신규 서비스 인프라로 OpenShift Cluster 도입, 운영·안정화 단계 기술지원.
  • 문제 1: 특정 파드 v2-6-istio-cni에서 Unauthorized 에러 로그 발생 및 ContainerCreating 상태 지속.
  • 문제 2: 특정 지역 교육청에서 L4 장비로 유입된 외부 Client IP 대역과 클러스터 내부 Pod CIDR 대역이 동일하여 서버가 외부로 응답하지 못하고 클러스터 내부에서 무한루프 발생.
② 해결 방식
  • 사례 1 (istio-cni): OSSM 2.4 이상에서 해결된 사안이나 kubeconfig 인증 정보 갱신 실패 등 불안정 요소로 OpenShift 4.16에서 발생할 수 있는 요소로 확인 → kubeconfig 인증 정보 갱신 후 istio-cni-node 파드 rollout.
  • 사례 2 (CIDR 중복): Infra Node의 Layer4 Packet SRC에 Client IP가 직접 노출됨을 확인(정상적으로는 VIP 노출) → 해당 교육청 L4 장비에 SNAT(Source NAT) 설정을 적용하여 Pod IP 대역과 겹치지 않도록 조치.
  • 기술지원: Helm chart 배포 디플로이먼트의 메모리 Request/Limits 설정 지원, 운영 내부망 클러스터에 Jenkins CI 도구 설치.
③ 성과
  • AS-ISv2-6-istio-cni Unauthorized 에러 및 ContainerCreating 상태 지속으로 파드 기동 불가
  • TO-BEkubeconfig 인증 정보 갱신 및 istio-cni-node 파드 rollout로 정상화
  • AS-ISClient IP 대역과 Pod CIDR 대역 중복으로 특정 지역 교육청에서 응답 불가·무한루프 발생
  • TO-BEL4 장비 SNAT 적용으로 Pod IP 대역과 겹치지 않도록 조치하여 통신 정상화
  • TO-BEPrivate OpenShift Cluster의 실무 안정적 운영 경험 축적
④ 한계와 개선
  • 대규모 OpenShift Cluster 운영 역량 보완을 위해 OpenShift 권장 아키텍처 직접 구성 및 Operator 설치 학습 진행 중 GitLab·Jenkins·ArgoCD·Harbor 기반 CI/CD 파이프라인 역량 확보 계획.
⑤ 프로젝트 아키텍처 (Archify 스킬)
