[한국직업능력심사평가원] CentOS7.9 EOL로 인한 RockyOS 9.4 기반 Apache HTTP Server/Tomcat/APM 웹시스템 구축 프로젝트

2025.02.20 ~ 2025.04.28

역할인프라 엔지니어 (서비스당 WEB 2대·WAS 2대, Tomcat Server당 멀티 인스턴스 설치·구성)
① 문제 발견
  • 상황: 한국직업능력심사평가원 웹 시스템이 EOL 도래한 CentOS 7.9 기반으로 운영.
  • 문제: EOL로 보안 업데이트가 중단되어 보안 취약점 리스크가 있고 지속 가능한 운영 기반이 필요.
  • 문제: Tomcat은 단일 인스턴스로 구동 중인 상태였고, 단일 인스턴스 아키텍처는 단일 장애점(SPOF)을 내포하고 있어 해당 인스턴스에 장애가 발생하면 서비스 중단으로 이어질 위험이 있었음.
② 해결 방식
  • 해결 과정: 각 직능평 서비스당 WEB 2대·WAS 2대를 설치·HA 구성하고 WEB-WAS 간 mod_proxy_http 모듈의 LoadBalancer 알고리즘으로 인스턴스 및 서버 간 부하분산.
  • 해결 과정: Tomcat 서버별 단일 인스턴스 운영에서 멀티 인스턴스로 구성하여 단일 장애점(SPOF)을 예방하고, 정상 구동 중인 인스턴스로 트래픽을 자동 우회하도록 개선.
③ 성과
  • AS-ISEOL 대상 CentOS 7.9 운영으로 보안 취약점 리스크 존재
  • TO-BEEOL 대상 OS 이관을 통해 보안 취약점 리스크 제거 및 지속 가능한 오픈소스 운영 기반 마련
  • TO-BEWAS 서버별 멀티 인스턴스(2ea) 구성으로 고가용성(HA) 확보 및 WEB-WAS 간 mod_proxy_http 모듈의 LoadBalancer 알고리즘 기반 부하분산 처리
④ 한계와 개선
  • 겉보기에 정상 구축된 시스템이라도 트래픽 규모에 맞는 OS 커널 파라미터 튜닝 없이는 안정적 운영이 어렵다는 점을 확인.
  • 미들웨어 설정과 함께 리눅스 커널 파라미터까지 구축 점검 범위에 포함할 필요성 확인.
⑤ 프로젝트 아키텍처 (Archify 스킬)
